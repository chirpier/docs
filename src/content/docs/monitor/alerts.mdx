# Alerts

Alerts are the records Chirpier creates when a policy triggers for an event definition.

Use the [Alerts page](https://www.chirpier.co/teams/alerts) to review alert state, inspect delivery attempts, and move incidents through their lifecycle.

## Alerts inbox

The alerts inbox helps teams answer four questions quickly:

- which policies are currently triggering
- which alerts have already been acknowledged
- whether the condition has recovered or still needs action
- whether a connector delivery failed and needs follow-up

## Typical workflow

From the alerts page, you can:

- scan alert title, severity, period, and trigger time
- open an alert to inspect the underlying event definition and policy details
- acknowledge an alert when someone is actively handling it
- resolve an alert once the condition is no longer actionable
- archive old or noisy alerts that should leave the active queue

## Statuses

Common alert states are:

- **Triggered**: the policy condition is met and the alert needs attention
- **Acknowledged**: someone has taken ownership of the alert
- **Resolved**: the alert has been handled or the condition is no longer actionable
- **Archived**: the alert is kept for history but removed from the active workflow

Use [Policies](/docs/monitor/policies) to define what creates alerts in the first place.
