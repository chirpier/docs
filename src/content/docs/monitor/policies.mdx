# Policies

Policies tell Chirpier how to evaluate an event definition over time and when to create an alert.

Use the [Policies page](https://www.chirpier.co/teams/policies) when you want a charted event to become an operational signal.

## Create a policy

Click **New Policy** on the [Policies page](https://www.chirpier.co/teams/policies), then attach the policy to the event definition you want to monitor.

### Basic settings

- **Enabled**: turn evaluation on or off
- **Event**: choose which event definition the policy watches
- **Title**: give the policy a clear, human-readable name
- **Description**: add optional context for responders

### Evaluation settings

- **Period**: the time window Chirpier evaluates, such as minute, hour, or day
- **Aggregate**: how values are combined in that window, such as sum, count, average, max, or min
- **Condition**: the comparison Chirpier runs against the aggregate, such as greater than or less than
- **Threshold**: the numeric value that determines whether the policy triggers
- **Severity**: the urgency level applied to the resulting alert

Once the policy is saved, Chirpier continuously evaluates incoming rollups for that event definition and creates alerts when the rule is met.

## Example

Suppose you emit the event `server_room.temperature_c` from a sensor service.

You might create a policy with:

- **Title**: Server room overheating
- **Period**: Minute
- **Aggregate**: Average
- **Condition**: Greater Than
- **Threshold**: 30
- **Severity**: Critical

That policy tells Chirpier to:

1. average all `server_room.temperature_c` values in each minute window
2. compare that result with `30`
3. create a critical alert when the threshold is exceeded
4. route alert deliveries to the configured connector

Pair this page with [Alerts](/docs/monitor/alerts) so responders know how to acknowledge, resolve, and archive the resulting alerts.
